# 企业人事管理系统（hr-management-system）

> 基于 [RuoYi-Vue-Plus](https://github.com/dromara/RuoYi-Vue-Plus) 6.X 二次开发的企业级人事管理系统，用于个人后端开发学习与项目实践。在框架原有权限、代码生成等基础能力之上，独立完成了员工档案管理、员工数据统计看板、缓存一致性等业务模块与后端功能。

## 技术栈

| 层次 | 技术 |
| --- | --- |
| 后端 | Java 21、Spring Boot、MyBatis-Plus、MapStruct |
| 权限/安全 | Sa-Token（RBAC 权限模型） |
| 缓存/中间件 | Redis、Redisson |
| 数据库 | MySQL 8 |
| 前端 | Vue 3、TypeScript、Vite、Element Plus（仅用于接口数据展示） |
| 其他 | Maven、Lombok、SpringDoc |

## 功能模块

- 员工档案管理：员工信息的增删改查、分页、导出，支持按姓名/手机号/部门/状态等条件查询
- 组织与岗位：部门树、岗位管理、员工与部门/岗位关联
- 数据字典：在职状态、学历、性别等枚举统一维护
- 员工统计看板：员工总数、在职/离职人数、按在职状态与学历维度的分布统计
- 系统管理：用户、角色、菜单、部门等基础后台能力（沿用框架）

## 个人主要工作与技术实现

1. **员工统计看板（聚合查询 + 缓存）**
    - 基于 MyBatis-Plus 的 `selectMaps + group by` 在数据库层完成按状态、学历的分组聚合，避免全量数据查出后在内存统计；
    - 统计结果属于“高频读、低频写”场景，使用 Redis 缓存聚合结果，降低数据库压力。

2. **缓存与数据库一致性（Cache-Aside）**
    - 查询时先读 Redis，未命中再查数据库并回写缓存，设置 5 分钟过期时间作为兜底；
    - 在员工新增、修改、删除**数据库操作成功后**主动删除统计缓存，下次查询自动重建，保证数据最终一致，避免脏数据长时间存在。

3. **工号唯一性校验**
    - 在 Service 层基于工号做唯一性判断，结合 MyBatis-Plus 逻辑删除（`@TableLogic`）过滤已删除数据，新增/修改复用同一套校验逻辑。

4. **接口防重提交**
    - 基于自定义 `@RepeatSubmit` 注解 + Spring AOP + Redis 的 `setIfAbsent`（SETNX）实现幂等拦截，防止表单重复提交产生脏数据。

5. **参数校验与统一异常处理**
    - 使用 JSR-303 分组校验（新增/修改分组）对手机号、邮箱、身份证号做正则校验，非必填字段兼容空值，校验异常由全局异常处理器统一返回。

6. **字段翻译**
    - 使用框架 `@Translation` 注解，将部门 id 在序列化时自动翻译为部门名称，单表查询无需手动关联。

## 数据库设计（核心表）

`hr_employee` 员工表：主键（雪花 ID）、工号、姓名、性别、部门 id、岗位 id、手机号、邮箱、身份证号、学历、入职日期、在职状态、逻辑删除标识及通用审计字段。

## 快速开始

1. 安装 JDK 21、Maven、MySQL 8、Redis；
2. 在 MySQL 中导入项目脚本目录下的建表与初始化 SQL；
3. 修改 `ruoyi-admin/src/main/resources/application-dev.yml` 中的数据库与 Redis 连接信息；
4. 启动后端主启动类（默认端口 8080）；
5. 前端目录执行 `npm install`、`npm run dev`，访问前端地址，默认管理员账号登录。
